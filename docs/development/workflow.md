# 开发流程

## 环境与目录

Node 版本约束以 package.json 为准，.nvmrc 提供开发版本；确切依赖以 package-lock.json 为准。使用 npm ci 重现安装，首次确认 Electron 运行时已下载。源码职责见架构文档，禁止通过修改构建产物修复问题。

## 一项变更的流程

1. 在模块文档明确场景、范围、输入输出、限制与验收标准。
2. 修改共享 DTO、preload 白名单与 main 来源/参数校验。
3. 实现业务服务和界面，覆盖空状态、加载、失败、取消及资源释放。
4. 执行授权范围内的检查，记录未验证项目。
5. 同步模块说明、受影响的架构文档与 CHANGELOG；重要取舍补充 ADR。

## 代码约定

TypeScript strict；错误不静默吞掉，IPC 只传可序列化数据。避免全局隐式状态和未使用依赖。当前只配置 .editorconfig 与类型检查，尚无 ESLint、格式化器或自动化 CI，不把它们写成已执行检查。

使用清晰的领域命名；公共抽象由真实重复驱动。提交说明解释问题、行为变化与验证限制。若使用 Git，建议按一项完整变更提交；当前扫描未发现 Git 仓库，初始化和远程托管需另行安排。

## 文档更新规则

功能事实只在对应模块集中维护，其他页面通过链接引用。新文档按 docs/README.md 的目录职责放置；避免长期使用“最新”“已经全部验证”等无日期、无范围的表述。
