# 数据生命周期与跨设备迁移

## 当前格式（未版本化）

接口文件名为 `http-requests.enc`，内容是 safeStorage 加密后的 JSON HttpRequest 数组。普通保存先在同目录下暂存，再替换原文件。Windows 默认目录为 `%APPDATA%\Alche Tools`，开发版与安装版共用，其他平台默认使用 Electron 的 `userData`。

接口文件尚无 schemaVersion、导入导出或自动恢复。加密文件依赖系统密钥环境，直接复制到其他机器、账户或重装后的系统可能无法解密。

## 存储目录设置与迁移

默认目录下的 `storage.v1.json` 记录 `version: 1` 与绝对目录路径 `directory`。应用级设置缺失时读取旧 `http-storage.v1.json`，两者都缺失时使用默认目录。首次成功切换后写入应用级文件，旧文件保留。设置损坏或版本未知时保留文件并报错，避免误写其他库。

Windows 默认库缺失时会先校验旧开发目录 `%APPDATA%\alche-tools` 的密文，再复制到默认目录，原件保留。两个旧目录均有数据时优先打开默认目录，旧开发库可在设置中选择原目录打开。

目标目录无接口文件时复制当前密文。目标已有文件时先验证可读，再询问是否直接打开该库。两种切换均保留原目录的文件，恢复默认也遵循相同规则。如果复制成功但设置写入失败，当前设置继续有效，目标副本可以在重试时打开。

恢复时先关闭应用，备份设置和各目录密文。如果自定义目录暂时不可用，恢复其连接后再打开应用。如果设置损坏，可在备份后将两个设置文件移出默认目录以恢复默认，再在应用中选择原自定义目录。

## 当前人工恢复边界

应用关闭后再复制原始文件到安全位置，连同应用版本、操作系统和备份日期记录。恢复前先保留现有文件；仅在原密钥环境可用时尝试替换。备份原始密文不能保证重装系统后的恢复。读取失败时保留文件，不删除、不新建覆盖。

## 外观偏好

渲染进程使用 localStorage 的 `alche-tools.theme.v1` 键保存单个值，允许 `system`、`light`、`dark`。首次使用无需迁移。键缺失、值无效或读取失败时使用系统外观，读取过程保留原值。可在外观面板重新选择以恢复偏好，写入失败时本次切换仍然生效。

## 已确认规划


支持手动导入导出以便换电脑。导出格式须独立于系统密钥；不能将当前 enc 文件直接称为跨平台导出文件。

## 实施前必须完成的设计

- 版本化文档封套：明确 format、schemaVersion、导出时间与请求列表；具体字段待设计确认。
- 首个迁移器识别当前无版本数组；未知新版本拒绝写入，旧格式迁移先备份。
- 导出区分可分享的脱敏配置与含秘密的迁移备份；默认是否剔除秘密、是否口令加密仍待确认。
- 导入先校验大小、字段和版本，预览条目与冲突；明确合并/覆盖策略，不静默覆盖同 ID。
- 迁移失败保持原文件；恢复操作应可撤回；禁止因密钥不可用回退明文。
- 每次发布说明数据兼容范围；旧版不能读取新版数据时，回退应用必须配套恢复旧备份。

## 验收要求

旧格式升级后内容一致；损坏和未知版本不覆盖原文件；重复 ID 导入有明确结果；三平台各自在可用密钥环境保存读取；跨设备导出导入后接口可编辑，秘密处理符合明确选择。上述能力目前均未实现或验收。
